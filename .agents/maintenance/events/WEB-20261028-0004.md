# WEB-20261028-0004: Prevent accidental selection on repeated Menu activation

## Summary
Prevent native repeated-click word or paragraph selection on the Menu trigger while preserving selectable navigation content.

## Reason
HC-261 reproduced double-click selection of the Menu label and triple-click selection extending into navigation text. The existing range persisted when the disclosure reopened.

## Actions
Cancel only the default of repeated primary-button mousedown on the summary control. Preserve the first click, all click activation defaults, keyboard activation, secondary buttons and panel text selection. Remove the listener with the existing Header abort lifecycle.

## Validation
The focused test failed before repair and passes after it. All 19 relevant Header, Home and Search tests and the normal 137-route build passed. Real Chromium single, double and triple clicks in both themes preserve native toggle parity and focus without creating a selection. Native Alt-drag selection of panel link text remains available and survives keyboard close/reopen. Three unchanged Lighthouse 12.8.2 mobile runs produced median LCP 2182.5604 ms, CLS 0.0112339471, TBT 0 ms and Performance 99.

## Result
The local successor removes accidental repeated-trigger selection without disabling content selection or changing accepted geometry and glass resources. Exact-successor independent review is retained separately.

## Rollback
Revert the scoped successor commit. Frozen accepted predecessors remain unchanged.

## Follow-up
Retain independent review and the separate HC-261 evidence packet. Prior HC-232 Owner acceptance remains historical; no downstream execution or release is implied.

## Notes
An initial automated panel drag began link dragging; the corrected native Chrome Alt-drag gesture verified actual link text selection. No global selection clearing or CSS user-select restriction was added.
