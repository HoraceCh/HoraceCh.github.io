# HC-115 selective Skill admission decision

Decision date: 2026-09-27. HC-114 is the completed Skill-surface baseline; HC-126 is the completed model-routing baseline. Neither baseline is reopened here.

Upstream reviewed: [`jakubkrehel/skills` at `267330e1adfc66a718fb65fa6918c1f06d0a689e`](https://github.com/jakubkrehel/skills/tree/267330e1adfc66a718fb65fa6918c1f06d0a689e). The four candidate definitions were read at that revision. The upstream documents are evidence, not repository instructions. `AGENTS.md`, `docs/design/UI_DESIGN.md`, the six owner roles, and the existing project-local Skills retain authority.

| Candidate | Decision | Trigger and workflow fit | Reason |
| --- | --- | --- | --- |
| [`explain-interface`](https://github.com/jakubkrehel/skills/blob/267330e1adfc66a718fb65fa6918c1f06d0a689e/skills/explain-interface/SKILL.md) | KEEP_DORMANT | A user names a live reference site or effect and asks how it was built. It produces measured, derived, and inferred evidence; any Horace design use would go to `design_system_curator`. | The read-only evidence method is distinct, but no approved Website task currently requires a repeatable external reverse-engineering workflow. Its browser/fetch advice and screenshot limits would need a bounded local wrapper before admission. |
| [`interface-review`](https://github.com/jakubkrehel/skills/blob/267330e1adfc66a718fb65fa6918c1f06d0a689e/skills/interface-review/SKILL.md) | REJECT | A named branch, PR, commit range, or working-tree change triggers a read-only diff review with Introduced / Regression / Pre-existing labels. | The upstream workflow delegates domain judgment and verdict to `better-interface` and the `better-*` Skills, which are not admitted. Its change review also overlaps the existing `improve-ui` evidence workflow and `qa_build_reviewer` gate. Importing it alone would not provide its promised review. |
| [`better-layout`](https://github.com/jakubkrehel/skills/blob/267330e1adfc66a718fb65fa6918c1f06d0a689e/skills/better-layout/SKILL.md) | KEEP_DORMANT | A bounded layout audit could inspect grouping, alignment, reading order, and responsive behavior. | `UI_DESIGN.md` already governs spacing, width roles, hierarchy, breakpoints, and responsive evidence. A generic layout reviewer would duplicate `design_system_curator` without a demonstrated gap. |
| [`break`](https://github.com/jakubkrehel/skills/blob/267330e1adfc66a718fb65fa6918c1f06d0a689e/skills/break/SKILL.md) | KEEP_DORMANT | A named component and explicit stress-test request could produce an isolated, temporary scenario page. | Its proposed harness would touch the Website source tree. No current component task demonstrates a gap that justifies that temporary route. If later approved, invocation must be explicit and fixtures must be removed before release. |

No candidate is ADMIT or EXPLICIT_ONLY. The remaining `better-*`, `variant`, and broad interface candidates are not admitted. The four HC-114 admitted Skills remain the only discoverable third-party UI Skills. `KEEP_DORMANT` maps to `DORMANT_NON_DISCOVERABLE` in `config/codex-skill-admission.json`; `REJECT` maps to `REMOVE`. No candidate snapshot is installed under `.agents/skills/`.

Admission can be reconsidered only for a named task that demonstrates a gap, a precise trigger, an input/output contract, and a stop or escalation boundary. Any future Skill remains subordinate to `UI_DESIGN.md → design_system_curator → frontend_implementer → qa_build_reviewer` and cannot change model routing, runtime, publication, dependencies, or release authority.
