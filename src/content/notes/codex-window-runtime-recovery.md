## Codex Desktop 无法打开（后台有进程但窗口不显示）排查与修复

### 事件摘要

| 项目 | 内容 |
|---|---|
| 环境 | Windows 11，ChatGPT 桌面端（Codex，Microsoft Store MSIX 版 `OpenAI.Codex`） |
| 症状 | 启动后任务管理器有 6+ 个 `ChatGPT` 进程，CPU 高占用，但**窗口始终不显示** |
| 直接根因 | `config.toml` 硬编码依赖的运行时目录被误删，应用每次启动都在**重装运行时**，但本次重装反复被中断，窗口始终未显示 |
| 触发场景 | 清理缓存时误删了 `runtimes` 目录（`%LOCALAPPDATA%\OpenAI\Codex\runtimes\`） |
| 关键机制 | Codex 启动会先**安装/校验本地运行时**（`cua_node`），本次观察到运行时未就绪时窗口未显示；具体启动机制仍需更多证据 |
| 修复方式 | 清理失败的 `.staging-*` 安装残骸，让应用不受打扰地完整重装一次运行时 |
| 验证结果 | 窗口恢复显示，`MainWindowHandle` 非 0 |

> **Important: 核心结论**
> 「后台有进程但窗口不出来」≠ 应用崩溃、GPU 问题、或窗口在屏幕外。在 Codex 桌面端上，本次记录中的原因是**本地运行时（cua_node）正在安装 / 安装失败**，窗口被「初始化未完成」挡住，而不是渲染失败。

> **Warning: 一次教训**
> 本次故障是**人为误删运行时目录**造成的。修复过程中又因「没等够安装时间」反复杀进程，导致每次重装都只生成 `.staging-*` 中间态就失败，堆积了 18 个残骸。**清理 Codex 缓存时，绝不能碰 `runtimes` 目录。**

### 用户可见症状

- 双击启动后，**没有任何窗口出现**。
- 任务管理器里能看到 6 个甚至更多 `ChatGPT.exe` 进程，其中某个 CPU 占用持续很高（几百秒）。
- 进程 `Responding = True`（进程活着，不是崩溃），但 `MainWindowHandle = 0`。
- 用 Win32 枚举窗口，能看到一个窗口存在（`vis=False`，即被创建但从未显示）。
- 反复重启、清缓存、甚至卸载重装（应用本身）都无效。

### 原因说明

#### 直接根因

`%USERPROFILE%\.codex\config.toml` 里硬编码了运行时路径，例如：

```toml
[mcp_servers.node_repl]
command = 'C:\Users\<user>\AppData\Local\OpenAI\Codex\runtimes\cua_node\440c4f095d41ea30\bin\node_repl.exe'

[mcp_servers.node_repl.env]
NODE_REPL_NODE_MODULE_DIRS = 'C:\Users\<user>\AppData\Local\OpenAI\Codex\runtimes\cua_node\440c4f095d41ea30\bin\node_modules'
NODE_REPL_NODE_PATH = 'C:\Users\<user>\AppData\Local\OpenAI\Codex\runtimes\cua_node\440c4f095d41ea30\bin\node.exe'
```

其中 `440c4f095d41ea30` 是**内容哈希目录名**。一旦 `runtimes\cua_node\` 被删除，应用启动时会尝试重建这个运行时：

1. 先在 `cua_node\` 下创建 `.staging-<hash>-<random>` 中间态目录，边下载边解压。
2. 解压完整后，把 `.staging-*` 重命名/移动为正式的哈希目录。
3. 本次记录中，这些运行时文件就位后窗口恢复显示；现有证据不能确定它们是所有版本显示窗口的必要条件。

本次安装被反复中断后，`.staging-*` 中间目录留在原地，运行时未完成安装，窗口持续未显示。其他环境仍需结合日志确认原因。

#### 为什么「窗口存在但 vis=False」

本次观察到窗口已创建但隐藏，结合运行时状态怀疑初始化未完成；单凭该现象不能排除 GPU 或窗口位置等其他原因。

#### 为什么 Store 版应用的特殊性会误导排查

- Store 版（MSIX）应用由系统 **AppModel / RuntimeBroker** 拉起，**本次尝试未观察到用户级环境变量生效**。本次 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-gpu` 未解决问题（写进 `HKCU\Environment` 也在本次尝试中未能解决问题）。
- 本次卸载重装应用本身没有解决运行时问题；这一结果不证明其他版本或环境也会如此。

### 定位步骤

#### 1. 确认是「进程在跑但窗口不显示」

```powershell
Get-Process | Where-Object { $_.Name -match 'ChatGPT|codex|node_repl|cua' } |
  Select-Object Name, Id, CPU, StartTime, Responding, MainWindowHandle
```

判断：
- `MainWindowHandle` 全为 `0` → 未找到该进程的主窗口句柄；还需结合窗口枚举和实际显示检查。
- 某进程 `CPU` 持续高（几百秒）→ 进程正在消耗 CPU；应结合日志检查，不能仅凭此认定正在安装运行时。

#### 2. 枚举窗口确认「窗口存在但隐藏」

用 Win32 `EnumWindows` 枚举目标进程的所有窗口，看 `IsWindowVisible` 和窗口矩形：

- 若找到窗口但 `vis=False` → 可能存在未显示窗口；可结合初始化日志检查，但不能单凭此排除渲染问题。
- 若完全没有任何窗口 → 继续核查进程、初始化日志、GPU 和 WebView2；不单凭窗口枚举确定原因。

#### 3. 检查运行时目录的状态（关键一步）

```powershell
# 看正式运行时目录（非 .staging）是否存在
Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\runtimes\cua_node" -Directory |
  Where-Object { $_.Name -notmatch '^\.staging' }

# 看有没有失败的 .staging-* 残骸
Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\runtimes\cua_node" -Directory -Filter '.staging-*'

# 看关键文件是否就位
$rt = "C:\Users\<user>\AppData\Local\OpenAI\Codex\runtimes\cua_node\<hash>\bin"
Test-Path "$rt\node.exe"; Test-Path "$rt\node_repl.exe"; Test-Path "$rt\node_modules"
```

判断：
- **一堆 `.staging-*` 残骸、没有正式目录、没有 `node_repl.exe`** → 是本次排查运行时安装的线索，不足以独立确定根因。
- 正式目录存在且 `node_repl.exe` 就位 → 文件存在不能证明运行时完整，应结合日志继续检查。

#### 4. 核对 config.toml 硬编码路径是否与磁盘一致

```powershell
# 从 config.toml 提取运行时路径，逐个 Test-Path
Select-String -Path "$env:USERPROFILE\.codex\config.toml" -Pattern 'runtimes\\cua_node'
```

config 引用的哈希目录不存在时，应先检查路径、版本和日志；本次已知目录曾被误删，之后通过重新安装恢复。

### 修复方案

#### 修复前检查与清理记录

先正常退出应用，并核对实际运行时安装路径和失败记录。本次案例确认相关进程退出后检查了特定运行时目录中的 staging 中间目录。处理前应核对目标并备份，避免影响正在使用的目录，不要对整个运行时或用户配置目录递归删除。

#### 2. 启动应用，然后**耐心等待、绝不打扰**

```powershell
explorer.exe "shell:AppsFolder\OpenAI.Codex_2p2nqsd0c76g0!App"
```

> **Important: 最重要的纪律**
> 启动后**不要反复杀进程、不要删文件**。本次运行时安装耗时约 **5–10 分钟**（受杀软实时扫描影响会更慢）。中途打断只会让 `.staging-*` 再次变成残骸，回到原点。

#### 3. 监控安装进度（只读，不打扰）

每隔 2–3 分钟执行一次，看运行时是否就位：

```powershell
# 1. 进程 CPU 是否还在增长（增长 = 在干活）
Get-Process | Where-Object { $_.Name -match 'ChatGPT' } | Select-Object Id, CPU, MainWindowHandle

# 2. node_repl.exe 是否已生成
Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\runtimes\cua_node" -Recurse -Filter 'node_repl.exe'

# 3. 正式哈希目录是否出现（.staging-* 被"扶正"）
Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\runtimes\cua_node" -Directory |
  Where-Object { $_.Name -notmatch '^\.staging' }
```

本次记录中，`node_repl.exe` 出现、正式哈希目录生成后，窗口恢复显示；这些文件就位本身不能保证其他环境中的窗口显示。

### 验证方法

#### 窗口恢复

```powershell
Get-Process | Where-Object { $_.Name -match 'ChatGPT' -and $_.MainWindowHandle -ne 0 } |
  Select-Object Id, MainWindowHandle
```

非零句柄只能说明存在主窗口句柄，不能单独证明用户可见；本次记录还观察到窗口实际恢复显示。

#### 运行时完整性

```powershell
$rt = "$env:LOCALAPPDATA\OpenAI\Codex\runtimes\cua_node"
Get-ChildItem $rt -Directory | Where-Object { $_.Name -notmatch '^\.staging' }  # 有正式哈希目录
Get-ChildItem $rt -Recurse -Filter 'node_repl.exe'                               # 存在
```

### 遇到问题时的排查顺序

1. 确认「进程在跑但窗口不显示」（`MainWindowHandle=0`）。
2. 枚举窗口，区分「窗口隐藏」vs「窗口未创建」。
3. 检查 `runtimes\cua_node\` 是否有 `.staging-*` 残骸、正式目录、`node_repl.exe`。
4. 核对 `config.toml` 硬编码的运行时路径是否在磁盘上真实存在。
5. 在确认路径和备份后处理失败的 staging 残骸。
6. 启动后耐心等 5–10 分钟，不杀进程、不删文件。
7. 监控 `node_repl.exe` 生成，窗口恢复。

### 常见错误

- **清理缓存时误删 `runtimes` 目录** —— 这是本次故障的直接诱因。缓存可删，`runtimes` 不能删。
- **反复杀进程** —— 运行时正在安装时杀进程，会让 `.staging-*` 变残骸，越修越糟。
- **用环境变量禁用 GPU 修 Store 版应用** —— 本次尝试未解决问题，不能据此推断所有 Store 应用行为。
- **卸载重装应用本身** —— 本次重装未解决问题，其他环境仍需单独判断。
- **以为窗口在屏幕外** —— 本次枚举发现窗口隐藏；仅凭这一状态不能排除其他原因。
- **误判为 GPU 合成失败** —— 混合显卡可能与渲染问题有关；本次「窗口存在且隐藏 + CPU 高占用」只是继续检查初始化和运行时的线索，不能单独判断根因。
